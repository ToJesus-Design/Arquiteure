Descreve. Nós tratamos da lei.

Plataforma autoevolutiva de arquitetura, engenharia e planeamento urbano focada no enquadramento legal português. Recebe a tua intenção em texto, voz ou foto e devolve projetos validados.

Como funciona

  1. Cria projeto indicando tipo, município e descrição livre.
  2. Descreve a intenção em texto, áudio ou através de fotografias do espaço.
  3. O motor extrai um programa funcional estruturado.
  4. O gerador produz N alternativas de layout 2D.
  5. O validador confronta cada layout com RGEU, RJUE, DL 163/2006, RJ-SCIE e PDM aplicável.
  6. Cada alternativa recebe um score legal/funcional/estético/económico.
  7. Arquiteto inscrito aprova explicitamente cada gate (LEGAL, URBAN, SAFETY, ACCESSIBILITY, STRUCTURAL).
  8. O exportador emite dossier PDF + DXF + memória descritiva conforme estrutura aceite por câmaras municipais.

Princípios

  • Nenhuma decisão é definitiva sem aprovação humana.
  • Cada escolha cita a regra técnica/legal aplicada.
  • Versões imutáveis em DAG — todas as alterações criam nova iteração.
  • Base de conhecimento autoevolutiva sobre fontes oficiais (DRE, PDMs).
  • Hipóteses do LLM marcadas explicitamente como [HIPÓTESE].

Modelo de dados


Project ─┬─ Asset (foto/audio/doc)
         ├─ Intent (programa extraído)
         └─ ProjectVersion (DAG imutável)
              ├─ Diagnosis
              ├─ Alternative (layout + scores + svgPreview)
              ├─ Decision (cita ruleIds)
              └─ ApprovalGate (LEGAL/URBAN/SAFETY/...)

Rule ──── RuleUpdate (changes pendentes de revisão)

AuditEvent (append-only, indexado por entity+entityId)


Princípios aplicados


    

  • Nada definitivo sem humano: ApprovalGate requer architectProcedure.
    • 

  • Citação obrigatória: Decision.ruleIds, Alternative cita regras avaliadas.
    • 

  • Imutabilidade: ProjectVersion nunca é alterada; mudanças geram nova versão.
    • 

  • Autoevolução controlada: RuleUpdate fica pendente até revisão.
